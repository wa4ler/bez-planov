# Проверка версии 1.0 — 13 ноября 2026

Локально пройдено: **28 unit/integration + 48 браузерных проверок**.

## Что проверено

- 15 проверок ядра: контекст положительных/отрицательных пожеланий; неравномерные обязательные расходы при общем бюджете; дневные лимиты; 31 день; питание и отдых; аллергии; плотные оплаченные события; транспорт; начальный адрес; безопасная замена и пересборка.
- 13 проверок сервера: отсутствие конфигурации; OAuth state/PKCE; cookies и hashes; одинаковый аккаунт на двух устройствах; изоляция разных пар; конфликт версий; CSRF; ограничения тела; истечение/отзыв сессий; отсутствие тестового входа в production handler; точность provider ID и ограничение повторных входов.
- 12 браузерных сценариев на каждом из четырёх экранов Chromium: 320×740, 390×844, 430×932, 1440×960.
- Полный подбор в три шага; отдельные ответы обоих; оплаченное событие и его время; календарь в UTC с сохранением московского времени; сохранение после перезагрузки.
- Общий бюджет 5 000 ₽ на два дня с билетом 3 000 ₽ в первом дне.
- Изменение дат сохраняет билеты и показывает конфликт.
- Закрепление, замена, отмена, исходная версия и отдельная копия.
- Миграция локальных маршрутов v4 без удаления источника.
- Кнопки OAuth, явный перенос гостевых маршрутов, общий кабинет, выход.
- Задержанные ответы не стирают новый ввод и не возвращают приватные данные после выхода.
- Изменения партнёра сохраняются, а конфликтующая локальная версия маршрута становится отдельной копией.
- Нет горизонтального переполнения; центр кнопок действий действительно принимает нажатие, а не перекрыт другой панелью; нет исключений JavaScript в выполненных сценариях.

## Как воспроизвести

```bash
npm ci
npm run test:unit
npx playwright install --with-deps chromium webkit
npm run test:browser
```

Локально использован Chromium 156 через `PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH=/usr/bin/chromium`. WebKit был скачан, но не запустился из-за отсутствующих системных библиотек. GitHub Actions устанавливает системные зависимости и запускает также iPhone WebKit. Результат CI нужно проверять отдельно; этот файл не объявляет его успешным заранее.

Локальные тесты кабинета используют изолированный имитатор OAuth в loopback dev-server и настоящий обработчик API/SQLite. Это проверяет нашу логику сессии, данных и конфликта, но **не подтверждает вход у настоящих Яндекса/Mail.ru или настройку Cloudflare D1**. Реальный вход, импорт календаря в iOS и использование на физическом iPhone остаются отдельными проверками после настройки.

Рабочая публикация main не заменялась в ходе этой локальной проверки. Наличие новой ветки или успешных тестов само по себе не подтверждает новую публикацию.

При первом общем прогоне CI все 12 сценариев WebKit прошли. Три поздних теста других экранов достигли общего лимита OAuth из-за одной тестовой IP-идентичности. Тестовые устройства изолированы; ограничение production не ослаблялось. Его работу отдельно проверяет тест: 30 попыток разрешены, 31-я получает 429, другой IP не заблокирован. Итоговый статус повторного CI смотрите в PR.
