# Без планов · общий день для двоих

Сайт: https://bez-planov.pages.dev · Cloudflare Pages · production branch `main`.

## Новая версия

Ветка `feat/simple-couple-planner` упрощает продукт до одного сценария:

1. Даты и общий бюджет пары.
2. Отдельные предпочтения каждого человека.
3. Темп, время, необязательные билеты — готовый маршрут.

На главной одна кнопка начала. Галерея направлений, дневник и нижнее меню убраны. Дополнительные настройки раскрываются по необходимости. Кабинет содержит общие маршруты и два профиля предпочтений.

Маршрут можно менять по остановкам, закреплять, отменять изменения, возвращать исходную версию, сохранять отдельной копией и скачивать в календарь. Исходная версия и до восьми последних состояний сохраняются вместе с маршрутом. Старые локальные данные v4 читаются без удаления исходных ключей. Данные гостя переносятся в аккаунт только по явному действию пользователя.

## Личный кабинет

Cloudflare Pages Functions + D1, вход через Яндекс ID или OAuth Mail. Один аккаунт провайдера открывает один кабинет пары с любого устройства. Пароли и OAuth-токены не попадают в клиентский код. Сервер использует HttpOnly cookie, одноразовый OAuth state, PKCE Яндекса, ограничение запросов и проверку версии при записи. Одновременные правки не перезаписываются молча.

**Настоящий вход требует настройки D1 и приложений провайдеров.** В среде разработки нет доступа к Cloudflare аккаунту и ключам OAuth. Без настройки вход честно отключён; гостевой планировщик остаётся рабочим. Тестовый провайдер существует только в локальном loopback-сервере и не включён в Pages Functions.

Пошаговая инструкция с iPhone: [docs/ACCOUNT-SETUP.md](docs/ACCOUNT-SETUP.md). Собственный домен и отправка писем для OAuth не нужны. Полный реальный вход Mail требует проверки типа приложения, выданного актуальным кабинетом Mail/VK ID. Внешний OAuth пока не подтверждён тестовыми приложениями.

## Планирование и ограничения

- От одного до 31 дня; связанные районы или независимые дни.
- Бюджет за день или весь период. Общий бюджет сначала распределяется на обязательные события и резервы, затем на остальные расходы.
- Положительные пожелания не превращаются в запреты; распознанные ограничения показаны перед созданием.
- Изменение дат сохраняет закреплённые события и требует разрешить конфликт периода.
- В длинной программе предусмотрены паузы на питание и отдых. При ограниченном времени/бюджете или занятых событиями окнах выводятся предупреждения.
- Переезды оцениваются по приблизительным редакционным координатам и выбранному транспорту. Для неизвестного адреса используется явно обозначенный запас времени. Это **не навигационный сервис**, реальную дорогу и пробки нужно проверить на картах.
- Расписания заведений, билеты, меню, погода и фактические цены не проверяются онлайн. Все суммы — бюджетные ориентиры. Бронирование и платежи не выполняются.
- Генеративный ИИ и платные API не подключены. Никакие платные сервисы не активируются этой веткой.

Фотография на главной иллюстрирует настроение, а не конкретное заведение. Загружается только одно фото вместо всей прежней галереи.

## Разработка

Node 24:

```bash
npm ci
npm run dev
```

Откройте http://127.0.0.1:8765 . Обычный локальный запуск не включает фиктивный вход. Для сохранения локальной D1-совместимой базы между запусками:

```bash
LOCAL_DB=.local/dev.sqlite npm run dev
```

Проверки:

```bash
npm run test:unit
npx playwright install --with-deps chromium webkit
npm run test:browser
```

Браузерные тесты проверяют узкие экраны, доступность кнопок, полный подбор, события, бюджет, версии маршрутов, экспорт, сохранение, изоляцию кабинетов и общие данные с двух устройств. Локальная имитация провайдеров проверяет наш серверный код, но не заменяет настоящий вход через Яндекс/Mail.ru. GitHub Actions выполняет unit + Chromium + WebKit.

## Структура

- `index.html`, `app-v1.css`, `app-v1.js` — новый интерфейс и состояние клиента.
- `catalog.js`, `planner-v04.js` — редакционная база Москвы и алгоритм.
- `functions/api/[[path]].js` — серверный OAuth, сессии и сохранение данных.
- `migrations/0001_accounts.sql` — схема D1.
- `scripts/dev-server.mjs` — только локальная разработка и тесты.
- `tests/` — проверки логики, сервера и браузеров.

Production branch остаётся `main`. Эту ветку сначала проверяют в Cloudflare preview. Слияние в main и готовность реального OAuth — отдельные подтверждаемые шаги; наличие кода не означает, что новая версия опубликована или регистрация уже включена.
