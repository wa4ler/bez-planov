# Без планов · общий день для двоих

Сайт: https://bez-planov.pages.dev · Cloudflare Pages · production branch `main`.

## Новая версия

Ветка `feat/simple-couple-planner` обновляет дизайн и ведёт к маршруту через четыре коротких шага:

1. Даты и общий бюджет пары.
2. Предпочтения первого человека.
3. Предпочтения второго человека.
4. Темп, время, необязательные билеты — готовый маршрут.

Главная показывает эмоциональное обещание, фотографии настроения и явно обозначенный пример дня. Основное действие — «Собрать наш маршрут». Раздел идей помогает выбрать настроение; он не подменяет индивидуальные ответы обоих участников. Навигация содержит главную, идеи, маршрут и кабинет. Во время анкеты мобильное меню скрыто, чтобы не мешать продолжению. Дополнительные настройки раскрываются по необходимости.

В кабинете доступны сохранённые версии маршрутов, два профиля предпочтений и любимые места. Гостевое сохранение явно отличается от общего кабинета на сервере. При ошибке загрузки способов входа можно повторить запрос; истёкшую сессию можно восстановить с сохранением несинхронизированных правок отдельно для прежнего аккаунта.

Маршрут можно менять по остановкам, закреплять, отменять изменения, возвращать исходную версию, сохранять отдельной копией и скачивать в календарь. Исходная версия и до восьми последних состояний сохраняются вместе с маршрутом. Старые локальные данные v4 читаются без удаления исходных ключей. Данные гостя переносятся в аккаунт только по явному действию пользователя.

## Личный кабинет

Cloudflare Pages Functions + D1, вход через Яндекс ID, OAuth Mail или VK ID. Один аккаунт провайдера открывает один кабинет пары с любого устройства. Пароли и OAuth-токены не попадают в клиентский код. Сервер использует HttpOnly cookie, одноразовый OAuth state, PKCE Яндекса и VK ID, ограничение запросов и проверку версии при записи. Одновременные правки не перезаписываются молча.

**Настоящий вход требует настройки D1 и приложений провайдеров.** В среде разработки нет доступа к Cloudflare аккаунту и ключам OAuth. Без настройки вход честно отключён; гостевой планировщик остаётся рабочим. Тестовый провайдер существует только в локальном loopback-сервере и не включён в Pages Functions.

Пошаговая инструкция с iPhone: [docs/ACCOUNT-SETUP.md](docs/ACCOUNT-SETUP.md). Собственный домен и отправка писем для OAuth не нужны. VK ID использует современный поток с PKCE и callback device_id; почта для него необязательна. Для VK нужен VK_CLIENT_ID в серверных настройках. Полный реальный вход Mail требует проверки типа приложения, выданного актуальным кабинетом Mail/VK ID. Внешний OAuth пока не подтверждён тестовыми приложениями.

## Планирование и ограничения

- От одного до 31 дня; связанные районы или независимые дни.
- Бюджет за день или весь период. Общий бюджет сначала распределяется на обязательные события и резервы, затем на остальные расходы.
- Положительные пожелания не превращаются в запреты; распознанные ограничения показаны перед созданием.
- Изменение дат сохраняет закреплённые события и требует разрешить конфликт периода.
- В длинной программе предусмотрены паузы на питание и отдых. При ограниченном времени/бюджете или занятых событиями окнах выводятся предупреждения.
- Переезды оцениваются по приблизительным редакционным координатам и выбранному транспорту. Для неизвестного адреса используется явно обозначенный запас времени. Это **не навигационный сервис**, реальную дорогу и пробки нужно проверить на картах.
- Расписания заведений, билеты, меню, погода и фактические цены не проверяются онлайн. Все суммы — бюджетные ориентиры. Бронирование и платежи не выполняются.
- Генеративный ИИ и платные API не подключены. Никакие платные сервисы не активируются этой веткой.

Фотографии иллюстрируют настроение, а не конкретные заведения. Второстепенные изображения загружаются отложенно. На главной есть пример маршрута, а в результате — интерактивная схема с пронумерованными остановками, выбором карточки, масштабом и списком. На схему попадают только места с координатами из каталога; адреса пользовательских событий и пауз не выдумываются. Линия показывает порядок остановок, а не проверенную дорогу.

Исследование первичных источников Paired, Tripster, GetYourGuide, Wanderlog и других продуктов, выводы для аудитории пар 18–40 лет и границы этих выводов: [docs/UX-RESEARCH-2026.md](docs/UX-RESEARCH-2026.md). Сценарии, формулировки и состояния интерфейса: [docs/UX-SCENARIOS.md](docs/UX-SCENARIOS.md). Конверсионные результаты пока не измерялись.

## Разработка

Node 24:

```bash
npm ci
npm run dev
```

Откройте http://127.0.0.1:8765 . Обычный локальный запуск не включает фиктивный вход. Для сохранения локальной D1-совместимой базы между запусками:

```bash
LOCAL_DB=.local/dev.sqlite npm run dev
```

Проверки:

```bash
npm run test:unit
npx playwright install --with-deps chromium webkit firefox
npm run test:browser
```

Браузерные тесты проверяют узкие экраны, доступность кнопок, четыре шага, поиск идей, схему маршрута, избранное, события, бюджет, версии маршрутов, экспорт, сохранение, изоляцию кабинетов и общие данные с двух устройств. Локальная имитация провайдеров проверяет наш серверный код, но не заменяет настоящий вход через Яндекс, Mail.ru или VK. GitHub Actions выполняет unit + Chromium + WebKit + Firefox.

## Структура

- `index.html`, `app-v1.css`, `app-v1.js` — новый интерфейс и состояние клиента.
- `experience-v2.js`, `experience-v2.css` — интерактивная схема маршрута и иллюстративный пример на главной.
- `catalog.js`, `planner-v04.js` — редакционная база Москвы и алгоритм.
- `functions/api/[[path]].js` — серверный OAuth, сессии и сохранение данных.
- `migrations/0001_accounts.sql` и `0002_vk_accounts.sql` — схема D1 и обновление для VK с сохранением существующих данных.
- `scripts/dev-server.mjs` — только локальная разработка и тесты.
- `tests/` — проверки логики, сервера и браузеров.

Production branch остаётся `main`. Эту ветку сначала проверяют в Cloudflare preview. Слияние в main и готовность реального OAuth — отдельные подтверждаемые шаги; наличие кода не означает, что новая версия опубликована или регистрация уже включена.

## Экраны и управление

Адаптивная раскладка для смартфонов, планшетов, ноутбуков и больших мониторов; портретная и альбомная ориентация, безопасные отступы для вырезов, крупные сенсорные кнопки, увеличенный текст, ввод с экранной клавиатурой и управление обычной клавиатурой. Проверки охватывают Chromium, WebKit и Firefox. Подробности и границы проверки: [docs/DEVICE-SUPPORT.md](docs/DEVICE-SUPPORT.md).
